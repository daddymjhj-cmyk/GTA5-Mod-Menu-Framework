## 🌱 Prologue — A Different Kind of README

Most README files read like a manual for a microwave. They tell you which button to press, where to plug the cord, and what temperature to select. This one is different. This one is a story about a **sandbox city** — a fictional metropolis where rules are flexible, physics is negotiable, and curiosity is the only currency that matters.

You are reading the documentation for a project that began its life as a spiritual sibling to the classic **GTA5-Trainer** repository. But instead of copying the idea verbatim, we took the original spark — the joy of shaping an open-world playground of your own design — and carried it into completely new territory.

The result is **Palmwood Reverie** — a modular companion toolkit for open-world simulation games. Think of it as a Swiss Army knife for virtual cities: a quiet, well-organized dashboard that hands you the controls, the maps, and the little quality-of-life instruments that make long sessions more pleasant.

If the original repository was a guitar, this one is a small orchestra — and you are the conductor.

## 🚀 Introducing the New Idea

**Repository name:** `palmwood-reverie`

**Tagline:** *Shape the sandbox. Conduct the chaos. Keep the chrome clean.*

Imagine you are handed a set of tuning forks, each humming at the frequency of a different subsystem inside an open-world game. One hums for the weather. Another for traffic density. A third for camera behavior. A fourth for pedestrian routines. A fifth for mission flow.

**Palmwood Reverie** is the resonator that lets all those forks sing together — gracefully, predictably, and without ever stepping on the toes of the base game.

Instead of positioning itself as a "modifier" or a "cheat suite," this project describes itself as a **scenario conductor**. It does not promise impossible power. It promises *control, clarity, and craft*. The kind of control that turns a chaotic playground into a curated stage.

The project is written with three audiences in mind:

- **Curious tinkerers** who want to understand what makes open-world simulation tick.
- **Content creators** who want reliable, repeatable setups for their recorded sessions.
- **Educators** who use virtual cities to demonstrate systems thinking, urban planning, or even AI behavior trees.

## 💡 Why This Project Exists

The original **GTA5-Trainer** ecosystem grew out of a simple desire: give the player a little more agency inside a world that often feels fixed. That desire has not gone away — it has matured.

Modern players do not just want switches. They want *dials*. They want sliders with meaning, toggles with consequences, and visual feedback that tells them exactly what a change did.

**Palmwood Reverie** exists to answer that maturing desire.

It is a reimagining of the classic companion-tool concept as a **modern, modular, and multilingual platform**. It borrows the spirit of the origin project but refuses to inherit its clutter. Every panel, every label, every animation is deliberate.

If a feature cannot justify its own existence in a sentence, it does not ship.

## 🧭 Feature Atlas

Below is the full atlas of what the project offers. Each feature is described from the angle of the *experience* it creates, not just the technical checkbox it ticks.

- 🎛️ **Control Deck** — A single, unified surface where every tunable parameter is grouped by domain (environment, traffic, population, camera, and mission flow). No more hunting through nested menus.
- 🗺️ **Live City Map** — An in-app map that reflects the current state of the sandbox in real time. Waypoints, zones, and points of interest appear as the world changes around you.

- 🚦 **Flow Tuning** — Adjust traffic density, pedestrian variety, and ambient activity with a small set of intuitive sliders instead of dozens of cryptic flags.
- 🎥 **Cinematic Lens** — Camera tools designed for creators: smooth follow, orbit, dolly, and shake suppression, all with a single toggle.
- 💾 **Profile Vault** — Save entire configurations as named profiles and switch between them instantly. Profiles are plain-text and human-readable.
- 🔌 **Plugin Port** — A documented extension interface that lets the community add new panels without touching the core.
- 🌍 **Multilingual Interface** — Full localisation framework with community-maintained translations.
- 📱 **Responsive UI** — The same dashboard scales gracefully from a large desktop monitor down to a compact windowed view.
- 🕰️ **Round-the-Clock Assistance** — A support desk that never sleeps, because inspiration rarely keeps office hours.

## 🏗️ Architecture Overview

The project is built around a small number of clearly separated layers. Each layer talks to the next through a well-defined contract, which makes the whole system easier to reason about — and much easier to extend.

- **The Kernel Layer** — The innermost ring. It knows how to talk to the host game in a safe, read-mostly fashion. It never assumes, always verifies.
- **The Bridge Layer** — A translation membrane that converts kernel events into a stable, versioned message format. If the host game changes beneath us, only this layer needs surgery.
- **The Domain Layer** — Where meaning lives. Weather, traffic, camera, population — each domain is a self-contained module with its own state, rules, and validators.
- **The Interface Layer** — The visible skin. A responsive, themeable UI that renders the domain layer as panels, sliders, and cards.
- **The Extension Layer** — The outermost ring, where community plugins dock. Extensions can add panels, presets, and translations but cannot reach past the bridge.
- **The Telemetry Layer** — An opt-in diagnostics bus that helps you and the maintainers understand what happened when something misbehaved. It carries no personal data.

This layered approach is the reason the project can evolve quickly without breaking the parts you love.

## 🖥️ Responsive UI Philosophy

A dashboard that only looks good on a 4K monitor is a dashboard that fails half its users. **Palmwood Reverie** treats responsiveness as a first-class design constraint, not a retrofit.

The layout uses a fluid grid that reflows based on available space. On wide screens, the Control Deck presents three columns of panels; on medium windows, two; on narrow windows, one. Sliders grow and shrink but never lose their precision. Typography scales without ever becoming illegible.

Three themes ship out of the box:

- **Daylight** — bright, high-contrast, easy on the eyes during long creative sessions.
- **Midnight** — deep, low-luminance, kind to late-night tinkerers.
- **Parchment** — warm, muted, and reminiscent of old cartography.

Every theme respects the operating system's reduced-motion preference, because accessibility is not an optional garnish.

## 🧩 Compatibility Matrix

The project is tested against a small but carefully chosen set of host environments. The matrix below reflects the 2026 state of the world.

- **Host Game Builds** — Tested against the two most recent major builds plus one legacy build for continuity.
- **Operating Systems** — Windows 10, Windows 11, and modern Linux distributions running the host through a compatibility layer.
- **Runtime Dependencies** — A single, bundled runtime. No system-wide installations, no dependency hunting.
- **Graphics Drivers** — Verified against the two most recent stable driver releases from the three major vendors.
- **Antivirus Coexistence** — Tested against the five most common consumer security suites to minimise false-positive noise.

If your configuration is not on this list, it does not mean it will not work — it simply means it has not yet passed through our verification gate. Contributions that broaden this matrix are warmly welcomed.

## ⚙️ Configuration Playbook

Every good tool has a rhythm. Here is how the project is best approached.

**First Movement — Explore the Defaults**
Launch the dashboard and do nothing. Watch the live map breathe. Notice how the panels update as the game world evolves. Understanding the baseline is the foundation of every meaningful change.

**Second Movement — Make One Change at a Time**
Pick a single slider. Move it. Observe. The project rewards slow, deliberate experimentation far more than frantic adjustments.

**Third Movement — Save a Profile**
Once a configuration feels right, name it and save it. Profiles are plain-text and portable, which means you can share them, version them, and archive them alongside your screenshots.

**Fourth Movement — Invite the World**
If a profile produced something beautiful — a sunset, a chase, a quiet street — consider sharing it. The community grows through generosity, not gatekeeping.

**Fifth Movement — Extend, Do Not Overwrite**
If the built-in panels do not cover your needs, write an extension rather than patching the core. Extensions are first-class citizens here.

## 🛠️ Extending the Project

The extension interface is documented in `EXTENSIONS.md` inside the repository. A condensed introduction:

- Extensions live in a designated folder and are discovered automatically at startup.
- Each extension declares a name, version, author handle, and a small manifest describing which panels it wants to contribute.
- Extensions communicate through the Bridge Layer only. They cannot, and should not, reach into the Kernel.
- Extensions are sandboxed. A misbehaving extension cannot crash the dashboard — it is isolated and can be disabled with a single click.
- The extension registry accepts community submissions through the standard pull-request flow.

The philosophy here is simple: **freedom with seatbelts**. You are encouraged to build boldly, protected from the consequences of accidents.

## 🔐 Security & Responsible Use

The project takes security seriously, both for your machine and for your peace of mind.

- **No Personal Data Collection** — The project does not track you, does not phone home by default, and does not store identifiers.
- **Opt-in Diagnostics** — Telemetry is off by default and can only be enabled by explicit action.
- **Sandboxed Extensions** — Extensions cannot access the filesystem beyond their dedicated folder or the network at all.
- **Signed Releases** — Every published build is accompanied by a cryptographic checksum so you can verify what you are receiving.
- **Responsible Use** — The project is intended for personal, offline, single-player enjoyment. Please respect the terms of service of any host game and the laws of your jurisdiction.

If you discover a security concern, please report it privately to the maintainers before disclosing it publicly. We would rather fix it quietly than see it exploited loudly.
